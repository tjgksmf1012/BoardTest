# A사이트 연동 가이드

이 커뮤니티는 **이미 회원을 가진 알바채용 사이트(기획서의 'A사이트') 안에 들어가는 기능**입니다.
그래서 아이디·비밀번호는 A사이트가 계속 관리하고, 커뮤니티는 그 회원번호에 매달린
**커뮤니티 프로필**(포인트·아바타·활동)만 가집니다.

---

## 1. 왜 커뮤니티에 따로 가입하면 안 되나요

A사이트 회원에게 커뮤니티 계정을 하나 더 만들게 하면 이런 일이 생깁니다.

| | 계정을 또 만들면 | 연동하면 |
|---|---|---|
| 가입 | 같은 사람이 두 번 가입 | A사이트 회원이면 **바로 이용** |
| 비밀번호 | 두 곳에서 따로 관리·변경 | A사이트 한 곳 |
| 탈퇴 | A사이트를 탈퇴해도 커뮤니티 계정이 남음 | 함께 정리됨 |
| 정지 | 커뮤니티에서 따로 정지해야 함 | A사이트 정지가 **바로 반영** |
| 보안 | 비밀번호를 한 벌 **더** 보관 (유출 지점 증가) | 커뮤니티는 비밀번호를 **갖지 않음** |

> 기획서 '아바타 해금 가이드'의 **"가입 후 바로 사용 가능"** 도 A사이트 가입을 뜻하는 것으로 보고 맞췄습니다.

---

## 2. 소유권 구분

| A사이트가 관리 (원장) | 커뮤니티가 관리 |
|---|---|
| 아이디·비밀번호, 본인확인 | 포인트, 포인트 내역 |
| 회원 상태(탈퇴·휴면·정지) | 아바타·테두리 해금/장착 |
| 운영자(관리자) 권한 | 출석 기록 |
| 회원번호(고유 키) | 글·댓글·추천·스크랩·신고·알림 |
| | 커뮤니티 닉네임 |

커뮤니티는 A사이트 DB를 직접 읽지 않습니다. **아래 토큰 하나만** 주고받습니다.

---

## 3. 동작 방식 (한 장 요약)

```
[A사이트]  회원이 '커뮤니티' 메뉴를 누름
    │      로그인 상태이므로 회원번호를 알고 있음
    │
    │  서명된 토큰을 만들어 주소에 붙여 이동
    ▼
  https://커뮤니티주소/board?sso=<토큰>
    │
[커뮤니티] 토큰 서명·유효시간 확인
    │      회원번호로 프로필을 찾고, 없으면 그 자리에서 생성(+1,000P)
    │      세션을 열고 토큰을 주소에서 떼어냄
    ▼
  https://커뮤니티주소/board       ← 로그인된 상태로 커뮤니티 이용
```

- 토큰은 **주소창·방문기록·Referer에 남지 않도록** 즉시 제거됩니다.
- 로그인이 필요한데 세션이 없으면 `HOST_LOGIN_URL` 로 보내고, 돌아올 주소를 `returnUrl` 로 함께 넘깁니다.

## 4. A사이트에서 만들어 주셔야 하는 토큰

### 형식

```
<payload>.<signature>

payload   = base64url( JSON )
signature = base64url( HMAC-SHA256(payload, 공유비밀키) )
```

### payload 항목

| 이름 | 필수 | 설명 |
|---|---|---|
| `uid` | **필수** | A사이트 회원번호 (사람을 가리키는 고유값, 문자열) |
| `iat` | **필수** | 토큰 만든 시각 (UNIX 초) |
| `nick` | 선택 | 표시할 닉네임. 없으면 커뮤니티가 자동 생성 |
| `admin` | 선택 | `true`면 커뮤니티 운영자 권한 |
| `banned` | 선택 | `true`면 이용 정지 상태 |

> `uid`는 **바뀌지 않는 값**이어야 합니다. 아이디처럼 변경 가능한 값 대신 내부 회원번호를 권장합니다.
> 개인정보(이름·연락처·이메일)는 **보내지 마세요.** 커뮤니티에 필요하지 않습니다.

### 예시 (Node.js)

```js
const crypto = require('crypto');

function makeSsoToken(member) {
  const payload = {
    uid: String(member.memberNo),      // 회원번호
    nick: member.nickname,             // 선택
    admin: member.isAdmin === true,    // 선택
    iat: Math.floor(Date.now() / 1000),
  };
  const body = Buffer.from(JSON.stringify(payload)).toString('base64url');
  const sig = crypto.createHmac('sha256', process.env.HOST_SSO_SECRET)
    .update(body).digest('base64url');
  return `${body}.${sig}`;
}

// 커뮤니티로 보낼 때
res.redirect(`https://커뮤니티주소/board?sso=${makeSsoToken(req.user)}`);
```

### 예시 (PHP)

```php
function makeSsoToken($member) {
  $payload = json_encode([
    'uid'   => (string)$member['member_no'],
    'nick'  => $member['nickname'],
    'admin' => $member['is_admin'] == 1,
    'iat'   => time(),
  ], JSON_UNESCAPED_UNICODE);
  $body = rtrim(strtr(base64_encode($payload), '+/', '-_'), '=');
  $sig  = rtrim(strtr(base64_encode(
            hash_hmac('sha256', $body, getenv('HOST_SSO_SECRET'), true)), '+/', '-_'), '=');
  return $body . '.' . $sig;
}
```

### 규칙

- 토큰은 **한 번 이동할 때마다 새로 만들어** 주세요. 기본 유효시간은 **5분**입니다.
- 공유 비밀키(`HOST_SSO_SECRET`)는 **32자 이상 무작위 값**으로, 서버 환경변수로만 보관해 주세요.
- 반드시 **HTTPS**로 이동해 주세요.

## 5. 커뮤니티 쪽 설정

```bash
AUTH_MODE=host
HOST_SSO_SECRET=<A사이트와 나눠 가진 비밀키>
HOST_LOGIN_URL=https://a-site.example.com/login
HOST_LOGOUT_URL=https://a-site.example.com/logout   # 선택
HOST_SSO_TTL_SEC=300                                 # 선택(기본 300초)
```

`AUTH_MODE`를 빼거나 `standalone`으로 두면 **지금처럼 자체 아이디/비밀번호로 혼자 돌아갑니다.**
(시연·심사용은 이 상태 그대로 쓰면 됩니다.)

## 6. 확인이 필요한 사항 (A사이트 담당자께 여쭐 항목)

연동 방식은 A사이트가 무엇을 줄 수 있는지에 따라 달라집니다. 아래만 알려주시면 맞춰 붙일 수 있습니다.

- [ ] **회원번호**로 쓸 수 있는 값이 있나요? (형식: 숫자/문자열, 길이, 변경 가능 여부)
- [ ] **닉네임**을 커뮤니티에 넘겨주실 수 있나요? 없으면 커뮤니티가 자동으로 만듭니다.
- [ ] **운영자(관리자) 여부**를 함께 넘겨주실 수 있나요? 아니면 커뮤니티에서 따로 지정할까요?
- [ ] 회원 **탈퇴·정지** 시 커뮤니티에 알려주실 수 있나요? (토큰의 `banned`, 또는 별도 통지)
- [ ] 커뮤니티가 **같은 도메인**에 붙나요, 다른 도메인인가요? (같은 도메인이면 세션 공유도 가능합니다)
- [ ] 커뮤니티 페이지를 **iframe으로 감싸시나요**, 아니면 링크로 이동하나요?
- [ ] A사이트 서버 언어/프레임워크는 무엇인가요? (위 예시 코드를 그에 맞게 드릴 수 있습니다)

### 이 방식 말고 다른 선택지

| 방식 | 조건 | 비고 |
|---|---|---|
| **서명 토큰** (현재 구현) | 도메인이 달라도 됨 | 가장 범용적. A사이트에 함수 하나만 추가 |
| 세션·쿠키 공유 | 같은 도메인 + 같은 세션 저장소 | A사이트 코드 수정 거의 없음 |
| 서버-서버 API 확인 | A사이트가 세션 검증 API 제공 | 요청마다 왕복이 생겨 느려짐 |

바꿔야 할 경우 `src/identity.js` 한 파일만 고치면 됩니다. 나머지 코드는 그대로입니다.

## 7. 연동 모드에서 달라지는 화면

| | standalone | host |
|---|---|---|
| 상단바 (로그아웃 상태) | 로그인 · 회원가입 | **로그인**만 |
| `/signup` | 가입 화면 | `/login`으로 넘김 |
| `/login` | 자체 로그인 화면 | **A사이트 로그인 화면으로 이동** |
| 로그아웃 | 커뮤니티만 | `HOST_LOGOUT_URL`이 있으면 A사이트까지 |
| 포인트 안내 | "회원가입 1,000P" | **"커뮤니티 첫 방문 1,000P"** |

기획서의 포인트·아바타 규칙은 두 모드에서 **완전히 동일**하게 동작합니다.
