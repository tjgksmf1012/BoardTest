## 4. 게시판 구조 (시안 1000004424 · 1000004425 · 1000004426 공통)

시안의 상단은 두 줄입니다.

```
채용정보  인재정보  [커뮤니티]  알바가이드  퍼스널가이드  광고등록     ← A사이트(호스트)
[밤알바커뮤니티]  이벤트·포인트게시판  출석체크                        ← 커뮤니티 안
```

즉 시안에서는 **게시판이 3개**(밤알바커뮤니티 / 이벤트·포인트게시판 / 출석체크)입니다.
그런데 수정사항 8번은 "**이벤트 카테고리** 추가"라고 되어 있어,
지금은 **게시판 1개 + 말머리(전체·자유·질문·정보·이벤트)** 로 만들었습니다.

**❓ 어느 쪽인지 확인 필요.** 게시판을 3개로 나누면 글·댓글·포인트 표는 그대로 두고
`posts.board` 한 칸만 늘리면 되지만, 화면과 주소가 달라집니다.

### 테두리 배치 — 가이드(시안 1000004429) 4번을 기준으로 맞췄습니다

가이드의 '움직이는 테두리' 는 **고리 안쪽이 캐릭터에 딱 붙어** 있습니다.
사이에 틈도 없고, 고리가 얼굴을 덮지도 않고, 고리 전체가 자기 칸 안에 들어갑니다.

받은 테두리 PNG 9장을 실측해 그 배치를 그대로 계산으로 옮겼습니다.

| 실측값 (그림 폭 대비) | |
|---|---:|
| 고리 몸통 안쪽 | 0.582 |
| 고리 몸통 바깥 | 0.836 |
| 밖으로 튄 반짝이 끝 | 0.961 |
| 안으로 뻗은 붓터치 끝 | 0.465 |

여기서 두 조건을 풀면 고리 크기가 정해집니다.

- 고리 바깥이 칸을 꽉 채운다 → 고리 그림 = 칸의 **120%** (0.836 × 1.20 = 1.00)

얼굴 크기는 계산으로 뽑았다가 한 번 틀렸습니다. 계산으로는 70% 가 나오는데,
**화면에는 캐릭터와 고리 사이에 흰 띠가 남았습니다.** 고리 안쪽 가장자리가 부드럽게
흐려져 있어서, 파일에는 색이 남아 있어도 눈에는 안 보이기 때문이었습니다.

그래서 **화면에 그려진 픽셀을 직접 재서** 정했습니다 → 얼굴 = 칸의 **72%**.

| 얼굴 크기 | 화면에서 잰 틈 |
|---:|---|
| 68% | 3.8% (흰 띠) |
| 70% | 2.2% (흰 띠) ← 계산으로 나온 값 |
| **72%** | **0.6% ← 딱 맞음** |
| 74% | −2.0% |
| 76% | −3.6% (고리가 얼굴을 문다) |

검사도 둘로 나눴습니다.

- `npm test` — 테두리 PNG 를 재서 **그림이 바뀌었는지** 지킵니다
- `npm run ring` — 브라우저로 그려서 **화면에서 딱 붙는지** 지킵니다
  (`--scan` 을 붙이면 얼굴 크기별로 훑어 딱 맞는 값을 찾아 줍니다)

안쪽으로 뻗은 반짝이 몇 점은 캐릭터 위로 올라옵니다. 가이드에서도 하트·별이
캐릭터 위에 얹혀 있어서 그림의 의도로 보고 그대로 뒀습니다.

## 8. 디자인 참고 사이트 — ✅ 확인함 (it'sALBA)

두 번째로 받은 캡처(`wix_corrected_verified_captures`)에서 실제 화면을 봤습니다.
첫 번째 캡처는 Wix 지연 렌더링 때문에 빈 화면만 찍혀 있었습니다.

**호스트 사이트 이름은 `it'sALBA`(잇츠알바)** 입니다.

| 요소 | 호스트 | 우리 (고치기 전) | 조치 |
|---|---|---|---|
| 주 강조색 | `#0ebaae` 밝은 민트 | `#0b8177` 짙은 틸 | `--brand` 추가 · 이후 `#0d9488` 로 연하게 ✅ |
| 탭 밑줄 | 민트 밑줄 | 짙은 틸 밑줄 | 민트로 맞춤 ✅ |
| 민트 배경 | `#e2fafa` | `#e2f2ef` | `#e2f7f5` 로 맞춤 ✅ |
| 카드 모서리 | 약 14px | 14px | 이미 같음 ✅ |
| 글꼴 | Pretendard 계열 | Pretendard 우선 | 이미 같음 ✅ |
| 상단 구성 | ☰ · 로고 · 🔔 · 프로필 / 밑줄 탭 | 밑줄 탭 | 같은 언어 ✅ |
| 하단 탭바 | **없음** (햄버거 메뉴로 이동) | 있음 | 아래 참고 |

### 강조색을 그대로 못 쓰는 이유 (그래서 두 개로 나눴습니다)

호스트의 민트 `#0ebaae` 는 **흰 글씨와의 대비가 2.4:1** 밖에 안 됩니다
(웹 접근성 기준 AA 는 4.5:1). 버튼에 그대로 쓰면 글씨가 흐려 보입니다.

그래서 두 가지로 나눴습니다. 색상(hue)이 거의 같아 한 식구로 보입니다.

- `--brand: #0ebaae` — **글자가 없는 곳**에만: 탭 밑줄, 진행바
- `--primary` — **흰 글씨를 얹는 곳**: 버튼, 뱃지

#### (추가) "초록이 너무 진하다" 는 회신을 받고 한 단계 연하게 옮겼습니다

`--primary` 를 `#0b8177` → **`#0d9488`** 로 바꿨습니다. 대신 이 색 위의 흰 글씨
대비가 4.75:1 → **3.74:1** 로 내려가 AA 기준(4.5:1)에는 못 미칩니다.
호스트 민트를 그대로 쓸 때(2.43:1)보다는 나은 자리이고, 요청하신 방향이라 그대로 뒀습니다.

기준을 다시 맞춰야 하면 `public/css/style.css` 의 `--primary` 한 줄만
`#0b857b` 로 되돌리면 됩니다(4.51:1 — 눈으로는 지금과 거의 구분이 안 갑니다).

### 캡처에 찍힌 우리 화면은 옛 버전입니다

`04~06` 캡처에 우리 커뮤니티가 들어가 있는데, **수정사항 반영 전 버전**입니다.
(알바후기·구인구직 말머리가 남아 있고, 전체글·인기글 세그먼트와 위쪽 검색창이
그대로 있고, 캐릭터가 글자 동그라미입니다.)
지금 버전으로 다시 한 번 넣어 보시면 좋겠습니다.

## ⚠️ 앞서 말씀드린 것 중 정정할 것 — 하단 탭바

지난번에 "연동하면 하단 탭이 두 줄이 된다"고 말씀드렸는데, **그렇지 않습니다.**

그건 교수님 시안(WIX Harmony 목업)에 하단 탭바가 그려져 있어서 그렇게 봤던 것이고,
**실제 it'sALBA 에는 하단 탭바가 없습니다.** 캡처 6장 어디에도 없고, 대신
왼쪽 위 햄버거(☰) 메뉴로 이동합니다.
