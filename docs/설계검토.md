# 남은 결정 8가지 — 다른 곳은 어떻게 하는지, 무엇을 권하는지

`docs/시안대조표.md` 에서 "물어봐야 한다"고 적은 것들을 하나씩 조사했습니다.

**먼저 밝혀둘 것** — 이 작업 환경의 네트워크 정책이 바깥 사이트 접속을 막고 있어
(모든 요청이 프록시에서 403) **경쟁 사이트를 직접 열어 보지는 못했습니다.**
검색으로 얻은 내용은 출처를 달았고, 나머지는 제가 아는 범위의 사례라 표시해 뒀습니다.
직접 확인이 필요한 대목은 그렇다고 적었습니다.

## 1. 게시판을 3개로 나눌까, 1개 + 말머리로 둘까

### 조사

말머리와 게시판 분리는 성격이 다릅니다. 게시판 분리는 아예 다른 공간을 만드는 것이고,
말머리·카테고리는 한 게시판 안에서 글을 나누는 것입니다.
운영자가 분류를 미리 정해두는 방식은 분류가 많아지면 감당이 안 되고,
말머리는 글마다 붙여 비슷한 효과를 냅니다.
([XETOWN](https://xetown.com/topics/1548338), [메일리](https://maily.so/tipster/posts/jl1zq14lr5x))

실제 사례 (제가 아는 범위):

| 서비스 | 방식 | 왜 그렇게 됐나 |
|---|---|---|
| 디시인사이드 | 갤러리(=게시판)마다 완전 분리 | 갤러리 하나가 이미 대형 커뮤니티라 나눠도 각자 돌아감 |
| 에브리타임 | 학교 안에 게시판 10여 개 | 학교당 이용자가 많아 분리해도 글이 채워짐 |
| 네이버 카페 | 게시판 트리 + 게시판별 말머리 | 카페 규모에 맞춰 운영자가 늘림 |
| 당근 동네생활 | **게시판 1개 + 주제 탭** | 동네 단위라 글 수가 적음 — 나누면 빈 게시판이 생김 |
| 알바몬 커뮤니티 | 주제 탭 | 위와 같음 |

**핵심은 하루에 글이 몇 개 올라오느냐**입니다. 게시판은 들어갔을 때 새 글이 몇 개는
보여야 다시 옵니다. 3개로 나누면 글이 1/3로 흩어집니다.
이제 막 여는 커뮤니티에서 가장 흔한 실패가 이것입니다.

### 그런데 시안의 3개는 성격이 다릅니다

```
[밤알바커뮤니티]   이벤트·포인트게시판   출석체크
```

- **밤알바커뮤니티** — 회원이 글을 쓰는 진짜 게시판
- **이벤트·포인트게시판** — 운영자가 이벤트를 올리고 포인트 규칙을 알리는 곳. 회원 글은 거의 없음
- **출석체크** — 게시판이 아니라 기능 화면

즉 **회원이 글을 쓰는 게시판은 원래 1개**이고, 나머지 둘은 성격이 다른 메뉴입니다.

### 권합니다 — 탭은 시안대로 3개, 글 게시판은 1개

```
[밤알바커뮤니티]        말머리: 전체 · 자유 · 질문 · 정보
[이벤트·포인트]          이벤트 말머리 글 + 포인트 적립 안내 (지금의 /points 를 합침)
[출석체크]               지금 그대로
```

- 시안의 화면 구성(탭 3개)과 수정사항 8번(이벤트 **카테고리** 추가)이 둘 다 지켜집니다
- 표는 `posts` 하나 그대로입니다 — 선배님이 PHP로 옮길 때 게시판 수만큼 표를 늘릴 필요가 없습니다
- 나중에 글이 많아져 정말 게시판을 쪼개고 싶으면 `posts.board` 한 칸만 늘리면 됩니다

**작업량**: 상단 메뉴 이름 바꾸기 + `/points` 화면에 이벤트 말머리 글 목록 붙이기.
반나절 정도입니다.

## 2. 전체글에서도 말머리 뱃지를 뺄까

### 조사

말머리는 그 게시판 안에서 글을 나누려고 제목 앞에 붙이는 표시입니다.
([네이버웍스 도움말](https://help.worksmobile.com/en/use-guides/board/post/set-label/))

거의 모든 게시판이 **전체 목록에서는 말머리를 보여주고, 특정 말머리를 고른 뒤에는
숨깁니다.** 이미 "질문" 탭에 들어와 있는데 모든 줄에 "질문"이 붙어 있으면 잉크만 낭비입니다.
네이버 카페가 정확히 이렇게 동작하고, 지금 우리 프로그램도 그렇게 되어 있습니다.

### 권합니다 — 지금 그대로 두기

시안 목록에 말머리가 없는 건, 그 화면이 이미 **"밤알바커뮤니티" 게시판 안**이라
붙일 말머리가 없어서일 가능성이 큽니다 (같은 시안의 상단 탭이 그 근거입니다).

다만 확실히 하려면 교수님께 **"전체글에서도 뺄까요?"** 한 줄만 여쭤보면 됩니다.
빼는 쪽으로 정해지면 `views/board.ejs` 한 줄 지우면 끝입니다.

## 3. 댓글의 레벨 뱃지(Lv.3)를 뺄까

### 조사

> 손님이 몇 명 안 되는 초반에 등급을 나누면 오히려 대부분의 손님이 최하위 등급에 머물러서
> 소외감을 느낄 수 있습니다. 등급과 포인트는 이미 자리잡은 브랜드에 어울리는 방식입니다.
> — [대시부스터](https://dashbooster.com/blog/early-fan-community-100-members-design)

실제 사례 (제가 아는 범위): 디시인사이드·에브리타임·더쿠·블라인드는 글·댓글 옆에
등급을 **안 보여줍니다.** 클리앙·뽐뿌·네이버 카페는 보여줍니다.
갈리는 지점은 **익명성**입니다. 익명성이 중요한 커뮤니티일수록 계급 표시를 뺍니다.

밤알바 커뮤니티는 익명성이 특히 중요한 판입니다. 신규 회원이 Lv.1로 시작해
Lv.5 옆에 글을 쓰면 위축됩니다.

### 권합니다 — 목록·댓글에서는 빼고, 프로필·랭킹에는 남기기

포인트가 이 프로그램의 핵심이라 레벨을 아예 없애면 동기가 사라집니다. 그래서 절반만:

- **뺄 곳**: 글 목록, 게시글 작성자 줄, 댓글 (읽는 흐름에 계급이 끼지 않게)
- **남길 곳**: 마이페이지, 랭킹, 공개 프로필 (보러 간 사람에게만 보이게)

**작업량**: 30분. 세 군데에서 `levelBadge(...)` 호출만 빼면 됩니다.

## 4. 이미지 첨부 — 본문 삽입식 vs 별도 첨부칸

이게 8개 중 **제일 중요합니다.** 나중에 바꾸면 이미 올라온 글을 손봐야 하기 때문입니다.

### 조사

오늘의집·당근마켓은 댓글 좋아요·대댓글·신고를 갖추고 당근은 댓글에도 이미지를 붙일 수
있는 반면, **알바몬 알바후기는 대댓글 없이 댓글·신고만** 있습니다.
([커뮤니티 게시판 기획 뿌시기](https://brunch.co.kr/@toqha7822/12))
— 같은 알바 업종이라도 기능을 덜어내는 쪽을 고른 사례입니다.

두 방식이 갈리는 기준:

| | 본문 삽입식 (지금) | 별도 첨부칸 (시안) |
|---|---|---|
| 쓰는 곳 | 네이버 블로그, 브런치, 티스토리 | 당근, 인스타, 오늘의집, 대부분의 모바일 커뮤니티 |
| 어울리는 글 | 사진과 글이 번갈아 나오는 **긴 글** | 사진 몇 장 + 짧은 글 |
| 모바일 | 커서를 원하는 자리에 두기가 어려움 | 누르면 끝 |
| 순서 바꾸기 | 잘라내서 옮겨야 함 | 끌어서 바꿈 |

### 그리고 선배님 쪽 사정이 하나 더 있습니다

지금은 **본문 HTML을 정규식으로 훑어서** 어떤 사진이 쓰였는지 알아냅니다.

```js
// src/richtext.js
const re = /<img[^>]+src="\/uploads\/([A-Za-z0-9._-]+)"/gi;
```

안 쓰는 파일 청소, 목록 썸네일, 공유 미리보기가 전부 이 함수에 매달려 있습니다.
**선배님이 PHP 5.1에서 이걸 다시 짜야 합니다.**

별도 첨부칸으로 가면 `post_images` 표를 조인하는 것으로 끝입니다. 본문을 파싱할 일이
없어집니다. DB 명세서에 이미 그 표가 들어 있습니다.

### 권합니다 — 시안대로 별도 첨부칸으로 바꾸기

모바일에서 쉽고, 시안과 같고, 넘겨받는 쪽이 훨씬 편합니다.
글이 아직 데모 5개뿐인 지금이 바꾸기 가장 싼 시점입니다.

**작업량**: 하루 정도 (첨부 UI, 순서 바꾸기, 목록·본문 출력, 기존 글 이전).
서식 도구의 굵게·밑줄·색은 그대로 두고 사진만 빼면 됩니다.

## 5. 글쓰기 화면의 "작성가이드 (?)" 에 뭘 넣을까

## 6. 안 쓰고 있는 PixAI 전신 그림 48장

**권합니다 — 지금 캐릭터로는 쓰지 않기. 대신 버리지도 않기.**

## 조사하다 새로 발견한 것 — 연동하면 하단 탭이 두 개가 됩니다

시안을 다시 보니 A사이트에도 하단 탭바가 있습니다.

```
시안:  홈 · 검색 · 최근본공고 · 커뮤니티 · 마이페이지     ← A사이트 것
우리:  홈 · 출석 · 글쓰기 · 랭킹 · MY                    ← 우리 것
```

지금은 우리 하단바가 **항상** 나옵니다. A사이트 안에 끼워 넣으면
화면 아래에 탭바가 두 줄로 겹칩니다.

**권합니다** — 연동 모드(`AUTH_MODE=host`)일 때는 우리 하단바를 끄고,
글쓰기 버튼만 오른쪽 아래 동그란 버튼으로 남기기. 상단 메뉴도 마찬가지입니다.
**작업량 1시간 정도.** 이건 물어볼 것 없이 필요한 일이라 다음에 할 일로 잡아두겠습니다.

## 그리고 되돌아본 것 — 베스트댓글을 없앤 게 맞았나

수정사항 11번대로 뱃지를 지웠더니 같은 댓글이 아무 표시 없이 두 번 나와서,
복사본을 없애고 정렬(최신순/추천순)로 바꿨습니다.

다만 **베스트댓글 자체는 한국 커뮤니티에서 매우 표준적인 장치**입니다.
네이버는 뉴스 댓글에 공감순·공감비율순 정렬을 두고 있고
([서울경제](https://m.sedaily.com/amparticle/11544479)),
네이버 카페·에브리타임·디시 모두 추천 많은 댓글을 위로 올려 줍니다.

그래서 두 가지 중에 고르시면 됩니다:

- **(A) 지금 상태** — 복사본 없음 + 최신순/추천순 정렬. 시안의 `최신순 ∨` 와 같음
- **(B) 되돌리기** — 맨 위에 "인기 댓글" 이라는 **글자 제목**을 달고 복사본 유지.
  수정사항이 지우라고 한 건 "뱃지"였으니, 뱃지 없이 제목만 다는 건 어긋나지 않습니다

**(A)를 권합니다.** 화면이 단순하고, 무엇보다 시안에 있는 장치입니다.
되돌리는 건 30분이면 됩니다.
