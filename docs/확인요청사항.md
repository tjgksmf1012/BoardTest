## Ⅰ. 회원 계정 연동 (이게 제일 먼저 필요합니다)

지금은 커뮤니티에 따로 회원가입하는 형태로 만들어 뒀습니다. 그런데 이미 A사이트 회원인 분한테
계정을 또 만들게 하는 건 아무래도 아닌 것 같습니다. A사이트 로그인 그대로 커뮤니티를 쓰게
붙이려면 아래를 알아야 합니다.

1. 회원을 구분하는 고유 번호가 있을까요? 숫자인지 문자인지, 그리고 한 번 정해지면 안 바뀌는
   값인지 알려 주세요.
2. 닉네임을 커뮤니티에 같이 넘겨 주실 수 있나요? 어려우면 커뮤니티에서 따로 정하겠습니다.
3. 운영자 권한을 A사이트 회원 정보로 알 수 있나요? 아니면 커뮤니티에서 따로 지정할까요?
4. 회원이 탈퇴하거나 이용 정지되면 커뮤니티에 알려 주실 수 있나요?
5. 커뮤니티가 A사이트와 같은 도메인에 붙나요, 다른 주소로 열리나요?
6. 커뮤니티 화면을 A사이트 안에 창처럼 넣으실 계획인가요, 그냥 링크로 이동하나요?
7. A사이트 서버는 무슨 언어로 되어 있나요? 알려 주시면 연동 예시 코드를 그 언어로 드리겠습니다.

연동 방법이랑 예시 코드는 따로 [연동가이드](연동가이드.md)에 정리해 뒀습니다.
개발 담당자분께 전달 부탁드립니다.

## Ⅱ. 게시판 구성

8. 기획 시안에는 게시판이 세 개(밤알바커뮤니티 / 이벤트·포인트게시판 / 출석체크)로 보이는데,
   지금은 게시판 하나에 말머리 다섯 종류로 만들어 뒀습니다. 어느 쪽으로 갈까요?
9. 말머리 항목은 이대로 쓸까요, 더하거나 바꿀 게 있을까요?
10. 익명 글쓰기는 그대로 열어 둘까요? 기획서에 익명글 포인트 규칙이 있어서 일단 넣어 뒀습니다.

## Ⅲ. 포인트 제도

11. 쌓인 포인트를 나중에 현금이나 상품, 쿠폰으로 바꿔 주실 계획이 있나요?
    있으면 포인트를 부정하게 모으는 걸 훨씬 강하게 막아야 해서 미리 알아야 합니다.
12. A사이트에 이미 포인트 제도가 있나요? 있으면 합칠지, 커뮤니티 포인트를 따로 둘지 정해 주세요.
13. 글이나 댓글을 지우면 받았던 포인트를 도로 가져올까요, 그냥 둘까요?

## Ⅳ. 캐릭터

14. 기획서 캐릭터는 예시라고 하셔서 저희가 새로 만들었습니다. 이대로 갈까요, 아니면 회사에서
    따로 만들어 주실까요? 주신다면 512×512 크기 PNG 로 주시면 됩니다.
15. 지금은 캐릭터가 다 여성인데 남성 캐릭터도 필요할까요?
16. 이벤트 한정 아바타(봄, 크리스마스, 할로윈)는 해당 시즌에 자동으로 열리게 해 뒀습니다.
    운영자가 직접 열고 닫는 방식이 더 나을까요?

## Ⅴ. 서버와 운영

17. 서버는 회사 서버에 올릴까요, 저희가 올려 둔 상태로 쓸까요?
18. 지금 DB 는 파일 하나로 도는 SQLite 입니다. 회사에서 쓰시는 DB 에 맞춰야 할까요?
19. 회원 수랑 동시에 접속하는 인원이 어느 정도일 것 같으신가요?
20. 첨부 사진을 서버에 그냥 저장해도 될까요, 따로 쓰시는 저장소가 있나요?
21. 개인정보 처리방침이랑 이용약관은 A사이트 것을 그대로 따르면 될까요?
22. 커뮤니티 운영자는 몇 분이고, 신고를 어떻게 처리할지 기준이 정해져 있나요?
23. 금칙어 거르는 기능이 필요할까요?
