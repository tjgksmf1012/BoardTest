# A사이트 연동 가이드

이 커뮤니티는 혼자 돌아가는 사이트가 아니라, 이미 회원을 갖고 있는 알바채용 사이트 안에
들어가는 기능입니다. 기획서에서 'A사이트' 라고 부르는 그 사이트입니다.

그래서 아이디랑 비밀번호는 A사이트가 계속 갖고 있고, 커뮤니티는 그 회원번호에 매달린
프로필만 갖습니다. 포인트, 아바타, 활동 기록 이런 것들입니다.

## 왜 커뮤니티에 따로 가입하게 하면 안 되나

A사이트 회원한테 커뮤니티 계정을 하나 더 만들게 하면 이런 일이 생깁니다.

같은 사람이 두 번 가입해야 하고, 비밀번호를 두 곳에서 따로 바꿔야 합니다. A사이트를 탈퇴해도
커뮤니티 계정은 그대로 남아 있고, A사이트에서 정지시킨 사람이 커뮤니티에서는 멀쩡히 글을 씁니다.
정지도 두 곳에서 따로 해야 한다는 뜻입니다.

무엇보다 비밀번호를 한 벌 더 보관하게 됩니다. 비밀번호를 갖고 있는 곳이 하나 늘어나면
털릴 수 있는 자리도 하나 느는 것입니다.

안 갖는 게 제일 안전합니다.

연동해 두면 A사이트 회원이 그냥 바로 이용할 수 있고, 정지나 탈퇴도 A사이트에서 한 번만
하시면 커뮤니티에 바로 반영됩니다. 커뮤니티는 비밀번호를 아예 안 갖습니다.

기획서 아바타 해금 가이드에 "가입 후 바로 사용 가능" 이라고 적혀 있는데,
저는 이게 A사이트 가입을 말하는 것으로 보고 맞췄습니다. 아니면 말씀해 주세요.

## 어느 쪽이 무엇을 갖고 있나

| A사이트가 갖는 것 | 커뮤니티가 갖는 것 |
|---|---|
| 아이디·비밀번호, 본인확인 | 포인트와 그 내역 |
| 회원 상태 (탈퇴·휴면·정지) | 아바타·테두리 보유와 장착 |
| 운영자 권한 | 출석 기록 |
| 회원번호 | 글·댓글·추천·스크랩·신고·알림 |
| | 커뮤니티에서 쓰는 닉네임 |

왼쪽은 A사이트가 원본을 갖고 커뮤니티는 받아서 쓰기만 합니다.

커뮤니티는 A사이트 DB 를 직접 읽지 않습니다. 아래에 적은 토큰 하나만 주고받습니다.

## 어떻게 도는지 한 장으로

```
[A사이트]  회원이 '커뮤니티' 메뉴를 누름
    │      이미 로그인해 있으니 회원번호를 알고 있음
    │
    │  서명한 토큰을 만들어서 주소 뒤에 붙여 보냄
    ▼
  https://커뮤니티주소/board?sso=<토큰>
    │
[커뮤니티] 토큰이 진짜인지, 시간이 안 지났는지 확인
    │      회원번호로 프로필을 찾고, 없으면 그 자리에서 만듦 (첫 방문 1,000P)
    │      로그인 처리하고 주소에서 토큰을 떼어냄
    ▼
  https://커뮤니티주소/board       ← 로그인된 상태로 커뮤니티 이용
```

토큰은 주소창이나 방문기록에 안 남게 바로 떼어냅니다. 안 그러면 주소를 복사해서 남한테
보내는 것만으로 그 사람 계정에 로그인이 돼 버립니다.

로그인이 필요한데 로그인이 안 되어 있으면 `HOST_LOGIN_URL` 로 보내고, 로그인 끝나고 돌아올
주소를 `returnUrl` 로 같이 넘깁니다.

## A사이트에서 만들어 주셔야 하는 토큰

토큰은 이렇게 두 덩어리를 점으로 이어 붙인 문자열입니다.

```
<내용>.<서명>

내용 = base64url( JSON )
서명 = base64url( HMAC-SHA256(내용, 나눠 가진 비밀키) )
```

내용에 담을 항목은 다섯 개인데, 이 중 위의 둘은 꼭 있어야 합니다.

| 이름 | 필수 | 무엇 |
|---|---|---|
| `uid` | 필수 | A사이트 회원번호 |
| `iat` | 필수 | 토큰 만든 시각 (UNIX 초) |
| `nick` | 선택 | 보여 줄 닉네임. 없으면 커뮤니티가 만듭니다 |
| `admin` | 선택 | `true` 면 커뮤니티 운영자 |
| `banned` | 선택 | `true` 면 이용 정지 상태 |

`uid` 는 절대 안 바뀌는 값이어야 합니다. 아이디처럼 나중에 바꿀 수 있는 값을 넣으면
그 사람이 아이디를 바꾸는 순간 포인트랑 캐릭터가 전부 날아갑니다. 내부 회원번호를 쓰시는 게
좋습니다.

그리고 이름이나 연락처, 이메일 같은 개인정보는 넣지 말아 주세요. 커뮤니티에서 쓸 일이
없는데 굳이 주소창에 실려 다닐 이유가 없습니다.

### 만드는 예시 (Node.js)

```js
const crypto = require('crypto');

function makeSsoToken(member) {
  const payload = {
    uid: String(member.memberNo),      // 회원번호
    nick: member.nickname,             // 없어도 됨
    admin: member.isAdmin === true,    // 없어도 됨
    iat: Math.floor(Date.now() / 1000),
  };
  const body = Buffer.from(JSON.stringify(payload)).toString('base64url');
  const sig = crypto.createHmac('sha256', process.env.HOST_SSO_SECRET)
    .update(body).digest('base64url');
  return `${body}.${sig}`;
}

// 커뮤니티로 보낼 때
res.redirect(`https://커뮤니티주소/board?sso=${makeSsoToken(req.user)}`);
```

### 만드는 예시 (PHP 5.1 에서도 도는 형태)

JSON 을 만들어 주는 `json_encode` 는 PHP 5.2 부터라 5.1 서버에서는 못 씁니다.
그런데 여기 담을 항목이 네 개뿐이라 문자열로 직접 만들어도 됩니다.
JSON 은 한글을 그대로 담아도 되니까 닉네임도 그냥 넣으시면 됩니다.

```php
<?php
// JSON 값 한 칸 만들기. 따옴표랑 역슬래시, 줄바꿈만 피해 주면 됩니다
function sso_str($s) {
    $s = str_replace(array('\\', '"'), array('\\\\', '\\"'), $s);
    $s = str_replace(array("\r", "\n", "\t"), array('\\r', '\\n', '\\t'), $s);
    return '"' . $s . '"';
}

function sso_b64url($raw) {
    return rtrim(strtr(base64_encode($raw), '+/', '-_'), '=');
}

function makeSsoToken($member, $secret) {
    $payload = '{'
        . '"uid":'   . sso_str((string)$member['member_no'])
        . ',"nick":' . sso_str($member['nickname'])
        . ',"admin":' . ($member['is_admin'] == 1 ? 'true' : 'false')
        . ',"iat":'  . time()
        . '}';
    $body = sso_b64url($payload);
    $sig  = sso_b64url(hash_hmac('sha256', $body, $secret, true));
    return $body . '.' . $sig;
}

// 쓰는 곳
$token = makeSsoToken($member, $HOST_SSO_SECRET);
header('Location: https://커뮤니티주소/board?sso=' . urlencode($token));
```

여기 쓴 `hash_hmac()` 은 PHP 5.1.2 부터 기본으로 들어 있습니다. 혹시 서버에 없으면
(`function_exists('hash_hmac')` 로 확인하실 수 있습니다) 말씀해 주세요.
PHP 코드로만 짠 것을 따로 드리겠습니다.

### 지켜 주셔야 할 것 세 가지

토큰은 한 번 이동할 때마다 새로 만들어 주세요. 만들어 놓고 계속 돌려 쓰시면 안 됩니다.
기본 유효시간은 5분입니다.

나눠 가질 비밀키(`HOST_SSO_SECRET`)는 32자 이상 아무렇게나 만든 값으로 해 주시고,
서버 환경변수에만 넣어 주세요. 코드 안에 적어 두시면 안 됩니다. 이 키가 새면 아무나
아무 회원인 척 토큰을 만들 수 있게 됩니다.

그리고 반드시 HTTPS 로 보내 주세요. HTTP 면 토큰이 그대로 흘러갑니다.

## 커뮤니티 쪽에서 할 설정

```bash
AUTH_MODE=host
HOST_SSO_SECRET=<A사이트와 나눠 가진 비밀키>
HOST_LOGIN_URL=https://a-site.example.com/login
HOST_LOGOUT_URL=https://a-site.example.com/logout   # 없어도 됨
HOST_SSO_TTL_SEC=300                                 # 없어도 됨. 기본 300초
```

`AUTH_MODE` 를 빼거나 `standalone` 으로 두면 지금처럼 자체 아이디와 비밀번호로 혼자
돌아갑니다. 시연하거나 심사받을 때는 이 상태 그대로 쓰시면 됩니다.

## A사이트 담당자분께 여쭤 봐야 할 것들

연동을 어떻게 붙일지는 A사이트가 무엇을 줄 수 있는지에 따라 달라집니다.
아래만 알려 주시면 거기 맞춰서 붙이겠습니다.

- 회원번호로 쓸 수 있는 값이 있나요? 숫자인지 문자열인지, 길이는 얼마인지, 나중에 바뀔 수 있는
  값인지 알려 주세요.
- 닉네임을 커뮤니티에 넘겨 주실 수 있나요? 안 되면 커뮤니티가 알아서 만듭니다.
- 운영자인지 아닌지도 같이 넘겨 주실 수 있나요? 아니면 커뮤니티에서 따로 지정할까요?
- 회원이 탈퇴하거나 정지될 때 커뮤니티에 알려 주실 수 있나요? 토큰의 `banned` 값으로 주셔도 되고
  따로 알려 주셔도 됩니다.
- 커뮤니티가 A사이트와 같은 도메인에 붙나요, 다른 도메인인가요? 같은 도메인이면 더 간단한
  방법도 있습니다.
- 커뮤니티 화면을 A사이트 안에 창처럼(iframe) 넣으시나요, 아니면 그냥 링크로 이동하나요?
- A사이트 서버는 무슨 언어로 되어 있나요? 알려 주시면 위 예시 코드를 그 언어로 드리겠습니다.

### 이 방식 말고 다른 방법도 있습니다

지금 만들어 둔 서명 토큰 방식은 도메인이 달라도 되고, A사이트에 함수 하나만 추가하면 되어서
제일 무난합니다. 그래서 이걸로 만들었습니다.

같은 도메인에 붙고 세션 저장소도 같이 쓰신다면 세션이랑 쿠키를 그대로 공유하는 방법이
있습니다. 이러면 A사이트 코드를 거의 안 고쳐도 됩니다.

A사이트에 세션이 유효한지 물어보는 API 가 있다면 요청할 때마다 물어보는 방법도 있는데,
매번 왕복이 생겨서 느려집니다.

어느 쪽으로 바꾸시든 커뮤니티에서는 `src/identity.js` 한 파일만 고치면 됩니다.
나머지 코드는 그대로 둬도 됩니다.

## 연동하면 화면이 어떻게 달라지나

| | 혼자 돌 때 | 연동했을 때 |
|---|---|---|
| 상단바 (로그아웃 상태) | 로그인 · 회원가입 | 로그인만 |
| `/signup` | 가입 화면 | `/login` 으로 넘김 |
| `/login` | 커뮤니티 로그인 화면 | A사이트 로그인 화면으로 |
| 로그아웃 | 커뮤니티만 | `HOST_LOGOUT_URL` 있으면 A사이트까지 |
| 포인트 안내 문구 | 회원가입 1,000P | 커뮤니티 첫 방문 1,000P |

포인트 문구가 바뀌는 건 가입을 A사이트에서 이미 했기 때문입니다.

기획서에 적힌 포인트랑 아바타 규칙은 두 방식에서 똑같이 돕니다.
